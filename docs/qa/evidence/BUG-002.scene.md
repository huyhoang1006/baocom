📌 TÓM LẠI:
  1. User mở /my-history → fetch GET /api/registrations
  2. Route → withAuth (token OK) → controller.getAll()
  3. Service → RegistrationRepository.findAll()
  4. 💥 Repository.include user không có select → trả full user row
  5. Controller pass thẳng ra response (không strip sensitive fields)
  6. Frontend nhận 58 occurrences của password bcrypt hash

💥 ROOT CAUSE: `RegistrationRepository.findAll()` thiếu `select` clause
   khi include user → leak `password` (bcrypt) và `tokenVersion`.

🔧 FIX:
```typescript
// RegistrationRepository.ts:14-20
async findAll(where?: Prisma.RegistrationWhereInput): Promise<Registration[]> {
  return this.prisma.registration.findMany({
    where,
    orderBy: { date: 'asc' },
    include: {
      user: {
        select: {  // ← THÊM select để giới hạn fields
          id: true,
          username: true,
          name: true,
          role: true,
          isActive: true,
          departmentId: true,
          department: {  // vẫn include department nhưng KHÔNG có password
            select: { id: true, name: true }
          }
        }
      }
    }
  })
}
```

⚠️ IMPACT:
- 58 bcrypt hash occurrences trong 1 response (với user có nhiều registration)
- Có thể kết hợp với timing attack hoặc dictionary để crack weak password
- Lộ `tokenVersion` cho phép attacker biết khi nào session thay đổi
- Tất cả employee đều trigger được (không cần admin)
