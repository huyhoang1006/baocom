📌 TÓM LẠI:
  1. User click "Đăng xuất"
  2. POST /api/auth/logout → xóa cookie client-side
  3. 💥 Logout KHÔNG bump tokenVersion trong DB
  4. JWT cũ stateless vẫn valid → attacker dùng được
  5. User tin an toàn nhưng thực tế session vẫn sống

💥 ROOT CAUSE: `app/api/auth/logout/route.ts` chỉ xóa cookie,
   không invalidate token ở server side. JWT là stateless nên
   cookie bị xóa không ngăn token bị reuse từ nơi khác.

🔧 FIX (1 dòng thêm + wrap withAuth):
```typescript
// app/api/auth/logout/route.ts
import { withAuth } from '@/lib/authMiddleware'
import { prisma } from '@/lib/prisma'

export const POST = withAuth(async (req, userId) => {
  // 💥 Bump tokenVersion → tất cả token cũ trở nên invalid
  await prisma.user.update({
    where: { id: userId },
    data: { tokenVersion: { increment: 1 } }
  })

  const response = NextResponse.json({ success: true })
  response.cookies.set('token', '', {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'lax',
    maxAge: 0,
    path: '/'
  })
  return response
})
```

Tại sao fix này hoạt động:
- `withAuth` middleware (authMiddleware.ts:21-27) đã check
  `user.tokenVersion !== payload.tokenVersion` → 401 "Session expired"
- Sau khi bump, token cũ có `tokenVersion=N`, DB có `tokenVersion=N+1`
  → mọi request cũ đều fail

⚠️ IMPACT:
- HIGH: User nghĩ logout = bảo vệ nhưng thực tế không
- Nếu attacker sniff cookie (public WiFi, malware, ...)
  → vẫn access được sau khi victim logout
- Đặc biệt nguy hiểm với admin account
- 7-day JWT expiry → cửa sổ tấn công rất dài
